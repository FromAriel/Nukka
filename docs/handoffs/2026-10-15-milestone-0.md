From the first session, which went from the original design doc through planning and a working headless game. Read `CLAUDE.md` first; it has the commands and code rules.

- `packages/combat`: the autopilot combat simulation (`autopilotResolver`, `createCombat(...).snapshot()` for future rendering).
- `packages/ai`: utility-planner bots; personalities are in `data/bots/*.json`.
- `packages/harness`: `pnpm sim` batch runner and metrics, `pnpm smoke`, data loaders, and the map generator. Tests that need data files live here.
- `pnpm check`: 132 tests, about 20 seconds.

**Milestone 0 acceptance:** 500 bot matches across all 7 personalities, with no errors or stuck decisions; replays reproduce exactly.

## What we learned

- **Balance (bots are crude, so treat these as leads):**
  - Expansionist wins 65% and Defender 4%. Taking neutral land is cheap (2 formations beat 2 militia) and scores well.
  - Nobody uses nuclear weapons. Release opens in about 22% of matches, but bots only commit retaliation plans.
  - Someone is eliminated in 29% of matches.
  - The round-7 leader wins 46% of the time.
  - Covert operations: about 37% succeed, 43% are foiled and 19% exposed.
  - Details are in `M0_Harness_Results.md`.
- **Battery placement decides air defense.** A gun next to the target barely fires before the bombs drop; one under the approach path shoots raids down. Build orders now take an optional `site`.
- **Speed:** about 145 ms per bot match, so 500 matches take about 75 seconds single-threaded. No worker threads are needed yet.

## What's left

**Small rule gaps (quick fixes):**

1. Covert Program isn't revealed on first use. A hidden silo launching should trigger `revealCovertPrograms` (`packages/core/src/engine/hidden-assets.ts`). Only Reconnaissance and Verification reveal it now.
2. Partial hits on hardened installations aren't saved. Combat computes steps from `inst.hardHits + hits` but never writes back the remainder (`packages/combat/src/sim.ts` `result()`, applied in `core/src/engine/operations.ts`).
3. Tied neutral claims should reset the territory to `match.neutral.militiaAfterTiedClaim`. Today the surviving militia is just left in place (`sim.ts` result plus `applyCombatResult`).

**Known simplifications:** see the table in `M0_Implementation_Notes.md`. Examples: allies can't take the stabilization slot, displaced population resettles instantly, ammunition is one national stockpile, and Emergency Relay isn't playable after sabotage.

**Milestone 1 needs:**
- Decision deadlines and timeouts (the safe defaults already exist in `defaultCommand`).
- Manual combat commands: aim, focus, withdraw.
- A command for choosing defense policy (everyone is Balanced today).

**Bots:**
- The Defender never expands.
- No bot calculates a first strike.
- Bots never accuse or trade.

**Docs tidy:**
- The planning docs need an index and a glossary.
- The original design doc still says "five economic measures" in places, and some parts predate later decisions.

## Notes (not obvious from the planning docs)

**About the user and how they work:**
- Works on Windows in PowerShell at `G:\Nukka`.
- Prefers concise summaries and makes design decisions in conversation; record those in the specs.
- Wants every number tunable, and expects to rebalance continually.
- Cares about cost:
  - GitHub Actions bills at least one minute per job, so CI runs only on PRs and pushes to `main`, as one job, and skips docs-only changes.
  - Opening a PR and merging it straight away runs CI twice. Push to `main` once, or merge after the PR's run.
  - Prefer short, focused sessions, and use cheaper models for routine work.

**Tooling gotchas:**
- **TypeScript is pinned to 6.** TS 7 breaks typescript-eslint.
- **esbuild must be approved to run its install script.** `pnpm-workspace.yaml` lists it under `onlyBuiltDependencies`.
- **Windows-specific:**
  - `tsx` must be a dependency of `packages/harness` itself, not only the root.
  - PowerShell splits `a,b,c` into separate words, so the CLI accepts spaces too.
  - `.gitattributes` forces LF line endings, or Prettier's check fails.
- **Editing files:**
  - Prettier reformats code, so string-replace scripts written against unformatted text silently miss. Use the Edit tool on the current text.
  - Vitest doesn't typecheck; `pnpm check` does.
- **`data/maps/` is generated and excluded from Prettier.** A test compares it byte for byte with its generator; run `pnpm gen:maps` after changing the generator.
- `NUKKA_DEBUG_REJECTIONS=1 pnpm sim ...` prints why the engine rejected bot commands.

**Engine design facts:**
- Core can't import combat. The combat resolver is injected through `MatchContext.combat`, and tests use scripted resolvers.
- Cards resolve after planning, so planning bonuses from cards apply next round. Full Mobilization was reworded to say so.
- Unfilled shadow slots are padded with blanks by the engine, identically for everyone.
- The crisis step runs in stages (`crisisStage`: vote → honor → commit → done). Release is decided fresh every round until the first nuclear use; after that, `release = 'aftermath'` for the rest of the match.
- Round 1 starts at planning. Upkeep begins in round 2.
- **Map numbers:** the map is 1200 × 1200: a 1000 × 1000 land grid of 200-unit cells inside a 100-unit ocean margin. Sea zone shapes are placeholders; the connection graph is what counts.
- **Cold-start scenario:**
  - It has an airfield so the aircraft has a base. That uses up all starting power.
  - It has no starting conventional bombs, so bots must build some before raiding.
- **Bots:** a bot returns ranked candidate commands. The runner submits them until one is accepted, then falls back to `defaultCommand`. Rejections are counted as a quality metric.
- **The view leak test** (`harness/src/views.test.ts`) plants canary values for one player and checks other views. It was confirmed to fail when a leak is introduced.
